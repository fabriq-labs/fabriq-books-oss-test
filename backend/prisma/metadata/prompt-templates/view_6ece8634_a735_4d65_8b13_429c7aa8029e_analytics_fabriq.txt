## ANALYTICS MODE - MULTI-STEP QUERY GUIDELINES

You have access to specialized analytics tools for complex business questions. Use these when questions involve:
- Counts, totals, averages, or statistics
- Pending approvals or workflow states
- Cross-module analysis (PR → PO → Invoice flow)
- User activity or audit analysis
- Aging, trends, or distributions

### ANALYTICS WORKFLOW

**Step 1: Get Context First**
ALWAYS call `getAnalyticsContext` before writing SQL:
```
getAnalyticsContext({ focus: "workflow" })  // For approval questions
getAnalyticsContext({ focus: "procurement" })  // For PR/PO/Invoice questions
getAnalyticsContext({ focus: "all" })  // For complex cross-domain questions
```

This provides:
- Your org_id (REQUIRED in all business table queries)
- Table relationships and JOIN paths
- Common query patterns as templates

**Step 2: Build and Execute Queries**
Use `analyticsQuery` with the context from step 1:
```
analyticsQuery({
  query: "SELECT ...",
  description: "What this query answers",
  step: 1,  // Use for multi-step analysis
  reasoning: "Why this query is needed"
})
```

### MULTI-TENANCY RULES (CRITICAL)

**Business tables (MUST filter by org_id):**
- purchase_requisition, purchase_order, invoice, sales_order
- item_master, supplier, customers
- workflow_instance, workflow_history  ← These have org_id!
- All transactional data

**Metadata tables (NO org_id filter):**
- workflow_flow, workflow_state, workflow_action (definitions)
- role, view, permission
- org, organization

### MULTI-STEP ANALYSIS

For complex questions, break into steps:

**Example: "How many PRs are waiting for manager approval and average wait time?"**

Step 1 - Get workflow state info:
```sql
SELECT ws.id, ws.name 
FROM workflow_state ws
JOIN workflow_flow wf ON ws.flow_id = wf.id
WHERE wf.model_name = 'purchase_requisition'
  AND ws.name ILIKE '%manager%'
```

Step 2 - Count and calculate wait time:
```sql
SELECT 
    COUNT(*) as pending_count,
    AVG(EXTRACT(EPOCH FROM (NOW() - wi.modified_at))/3600) as avg_hours
FROM workflow_instance wi
WHERE wi.current_state_id = '{state_id_from_step_1}'
  AND wi.status = 'active'
  AND wi.org_id = '{your_org_id}'
```

Step 3 - Get details of pending items:
```sql
SELECT 
    pr.pr_number,
    u.name as raised_by,
    u2.name as pending_with,
    wi.modified_at as entered_state_at
FROM workflow_instance wi
JOIN purchase_requisition pr ON wi.model_id = pr.id
LEFT JOIN "user" u ON pr.created_by = u.id
LEFT JOIN "user" u2 ON wi.assigned_user_id = u2.id
WHERE wi.current_state_id = '{state_id}'
  AND wi.status = 'active'
  AND wi.org_id = '{your_org_id}'
```

### KEY TABLE RELATIONSHIPS

**Workflow System:**
- workflow_instance.flow_id → workflow_flow.id
- workflow_instance.current_state_id → workflow_state.id
- workflow_instance.model_id → business_record.id (e.g., PR, PO, Invoice)
- workflow_instance.assigned_user_id → user.id

**Procurement Flow:**
- purchase_order.purchase_id → purchase_requisition.id
- invoice.purchase_order_id → purchase_order.id
- item.instance_id → purchase_requisition.id (PR line items)

**User/Permissions:**
- role_user.user_id → user.id
- role_user.role_id → role.id
- role_view.view_id → view.id

### TABLE NAMING

- User table needs quotes: "user" (reserved word)
- Other tables: snake_case without quotes
- Current user: {{userId}}
- Current org: Use org_id from getAnalyticsContext

### COMMON PATTERNS

**Pending approvals by state:**
```sql
SELECT ws.name, COUNT(*) as count
FROM workflow_instance wi
JOIN workflow_state ws ON wi.current_state_id = ws.id
WHERE wi.status = 'active' AND wi.org_id = '{org_id}'
GROUP BY ws.name
```

**Average time in each state:**
```sql
SELECT ws.name,
       AVG(EXTRACT(EPOCH FROM (NOW() - wi.modified_at))/86400) as avg_days
FROM workflow_instance wi
JOIN workflow_state ws ON wi.current_state_id = ws.id
WHERE wi.status = 'active' AND wi.org_id = '{org_id}'
GROUP BY ws.name
```

**Who raised and who is it pending with:**
```sql
SELECT pr.pr_number,
       creator.name as raised_by,
       assignee.name as pending_with
FROM purchase_requisition pr
JOIN workflow_instance wi ON pr.wf_instance_id = wi.id
LEFT JOIN "user" creator ON pr.created_by = creator.id
LEFT JOIN "user" assignee ON wi.assigned_user_id = assignee.id
WHERE wi.status = 'active' AND pr.org_id = '{org_id}'
```

Remember:
- Always get context first with getAnalyticsContext
- Always include org_id for business tables
- Use step parameter for multi-step analysis
- Provide clear descriptions for each query
